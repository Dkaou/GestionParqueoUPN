Guía Oficial de Exposición

Gestión de Parqueo UPN

Presentación interactiva del proyecto para la Evaluación T1. Sigue estos puntos clave para tu sustentación.

1

Diagramas de la Base de Datos

El sistema está diseñado en 8 tablas principales enfocadas en registrar quién entra, con qué vehículo, dónde se cuadra y qué pasa si comete una infracción.

El Núcleo

Usuarios y Vehiculos. Un usuario puede tener varios vehículos.

La Transacción

Cuando un vehículo entra, genera un Ticket que lo une a un Espacio y guarda la hora.

Penalidades

Las reglas rotas se vuelven Infracciones, que generan Sanciones canceladas mediante Pagos.

2

Restricciones e Integridad (B y C)

Diseñamos la base de datos con integridad referencial y restricciones estrictas para evitar datos basura.

Ejemplos clave a mencionar:
  • Usuarios: El DNI es CHAR(8) y Primary Key. El correo tiene UNIQUE.
  • Tickets: La duración en minutos es una columna COMPUTED (se calcula sola usando DATEDIFF).
  • Espacios: Tiene CHECK para que solo acepte estados "Disponible", "Ocupado" o "Mantenimiento".
3

Procesos de Inserción (D)

Creamos 7 Procedimientos Almacenados para ingresar información, protegiendo el sistema.

Por qué son importantes:

No insertamos datos a ciegas. sp_InsertarUsuario revisa que el DNI no exista antes de insertar; si existe, lanza un error limpio sin "reventar" la BD gracias al bloque TRY...CATCH.

4

El Proceso Estrella: Ingreso Vehicular (E)

El SP sp_RegistrarIngresoVehicular es el cerebro del sistema. Usa 3 Funciones Escalares para hacer 5 validaciones antes de levantar la talanquera.

Validaciones de Reglas

  • ¿Existe el carro?
  • ¿Ya tiene otro carro adentro?

Llamada a Funciones

  • fn_TieneDeudas: Si debe multas, NO ENTRA.
  • fn_TieneSuspension: Si está castigado, NO ENTRA.

Asignación de Espacio

  • Busca espacio para su tipo de vehículo. Si pasa todo, le genera el Ticket.
5

Automatización con Triggers (F, G, H)

Auditoría (XML)

Cuando se inserta/actualiza un usuario o pago, se guarda un registro en Historial_Auditoria con los datos viejos y nuevos en formato XML.

Estado Automático

Al generar un ticket de ingreso, el espacio pasa a "Ocupado". Al registrar salida, pasa a "Disponible" sin intervención humana.

Calculadora de Deuda

Al registrar una infracción nueva, el trigger suma todas las multas impagas del alumno y muestra el total.

6

El Cursor: Multa por Exceso (I)

A veces los alumnos dejan el carro más de 12 horas. El SP sp_ProcesarPermanenciaExcedida usa un CURSOR. Recorre fila por fila los tickets abiertos, calcula el tiempo y si excede 12 horas, le aplica una infracción de S/ 20.00 automáticamente, cuidando de no cobrar doble.

Discurso de Cierre (Lee esto al final)

"Profesor, el sistema no es solo un registro de datos. Es un sistema reactivo. Usa Procedimientos Almacenados para validar la integridad antes de insertar, usa Funciones modulares para consultar deudas que alimentan el SP principal, y usa Triggers y Cursores para automatizar el estado de los espacios, la auditoría en XML y la penalización automática, garantizando que todo el proceso funcione por sí solo."

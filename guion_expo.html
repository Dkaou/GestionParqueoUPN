Punto A

Diseño de la Base de Datos

👉 [Muestra en pantalla la página web de los diagramas]

"Buenos días profesor. Para este proyecto de Gestión de Parqueo UPN, diseñamos la base de datos dividida en 8 tablas principales. Como puede ver en el modelo, tenemos las tablas núcleo que son Usuarios y Vehículos, luego tenemos la gestión física con Zonas y Espacios de Parqueo. El proceso principal se registra en la tabla Tickets, y si ocurre algún problema, tenemos el flujo de Infracciones, Sanciones y Pagos."

Puntos B y C

Creación de la BD y Restricciones

👉 [Abre tu SQL Server y muestra las tablas y constraints]

"Sobre la creación, aplicamos integridad referencial estricta. Usamos llaves foráneas en todas las relaciones. Además, implementamos restricciones CHECK y UNIQUE. Por ejemplo, en la tabla Usuarios el correo es UNIQUE para evitar duplicados; en EspaciosParqueo hay un CHECK para que solo acepte estados 'Disponible', 'Ocupado' o 'Mantenimiento'; y en Tickets agregamos una columna computada que calcula automáticamente la duración en minutos usando DATEDIFF."

Punto D

Procedimientos de Inserción

👉 [Muestra en el SQL el código de 'sp_InsertarUsuario' o 'sp_InsertarVehiculo']

"Para no insertar datos directamente a las tablas, creamos 7 Procedimientos Almacenados básicos de inserción, uno por cada tabla. Lo importante aquí es que todos tienen validaciones preventivas. Por ejemplo, antes de insertar un usuario, verificamos si el DNI ya existe; si existe, detenemos el proceso con un RAISERROR dentro de un bloque TRY-CATCH."

Punto E

SP Principal (Registro Vehicular) y Funciones

👉 [Muestra el código de 'sp_RegistrarIngresoVehicular' y resalta las llamadas a las funciones 'dbo.fn_TieneDeudas']

"Este es el núcleo lógico del sistema. El SP de ingreso vehicular hace 5 validaciones secuenciales. Para lograr esto limpiamente, desarrollamos 3 funciones escalares: una para ver si tiene deudas, otra para calcular el monto, y otra para suspensiones. El SP verifica: 1) Que la placa exista. 2) Que el usuario no tenga otro vehículo adentro. 3) Usa la función para bloquearlo si tiene deuda. 4) Lo bloquea si está suspendido. Y 5) Busca dinámicamente un espacio libre para su tipo de vehículo."

Punto F

Auditoría con Triggers y XML

👉 [Muestra la tabla 'Historial_Auditoria' o el código de 'trg_Auditoria_Usuarios']

"En cuanto a seguridad, implementamos Triggers de Auditoría (AFTER INSERT, UPDATE, DELETE) en las tablas críticas como Usuarios y Vehículos. Estos triggers capturan qué usuario hizo el cambio, en qué fecha, y lo más importante: convierten los registros eliminados o insertados a formato XML para guardar el antes y el después exacto en la tabla Historial_Auditoria."

Punto G

Automatización: Estado del Espacio

👉 [Muestra el código del trigger 'trg_ActualizarEstadoEspacio']

"Para evitar errores humanos, la tabla EspaciosParqueo se actualiza sola. Creamos un trigger en la tabla Tickets. Si se inserta un ticket nuevo (entra un auto), el trigger automáticamente hace un UPDATE al espacio y lo marca como 'Ocupado'. Cuando al ticket se le hace un UPDATE para registrar la salida, el trigger libera el espacio poniéndolo 'Disponible'."

Punto H

Trigger: Total a Pagar

👉 [Muestra el código de 'trg_CalcularTotalPagar']

"También agregamos el trigger de multas. Cuando se inserta un nuevo registro en la tabla Infracciones, este trigger se dispara. Lo que hace es sumar todas las sanciones activas de ese usuario y lanza un mensaje PRINT alertando del monto total acumulado que el usuario debe pagar en ese momento."

Punto I

El Cursor: Permanencia Excedida

👉 [Muestra el código de 'sp_ProcesarPermanenciaExcedida' donde está el comando DECLARE CURSOR]

"Finalmente, profesor, implementamos el Cursor. Este cursor se encarga de penalizar a los que se quedan dormidos en el parqueo. Recorre fila por fila la tabla de Tickets buscando vehículos que lleven más de 12 horas sin hora de salida registrada. Si encuentra uno, automáticamente le genera una infracción por 'Permanencia Excedida' de 20 soles, verificando antes no duplicarle la multa. Así completamos la automatización total del sistema."

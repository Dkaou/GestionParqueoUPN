Guion Completo de Exposición

Discurso fluido para leer de corrido durante la presentación.

1. Introducción al Problema y Solución

"Buenos días profesor y compañeros. Hoy presento el Sistema de Gestión de Parqueo Vehicular para la UPN. El objetivo de este proyecto no fue solo crear un registro de entradas y salidas, sino desarrollar una base de datos reactiva y automatizada que pueda tomar decisiones por sí sola, validar reglas de negocio en tiempo real y penalizar automáticamente a los infractores, garantizando el orden dentro del campus."

2. El Diseño y Estructura

"Para lograr esto, diseñamos un Modelo de Base de Datos estructurado en 8 tablas principales. El flujo es simple: Tenemos a los Usuarios (alumnos o docentes) que poseen Vehículos. Estos vehículos ocupan Espacios de parqueo dentro de distintas Zonas. Cada vez que un vehículo entra, se genera un Ticket transaccional. Si el alumno incumple las normas, ese ticket deriva en Infracciones, que a su vez generan Sanciones económicas que se cancelan mediante la tabla Pagos.

Todo este diseño fue implementado en SQL Server usando integridad referencial estricta. Además, blindamos las tablas con restricciones CHECK (para que los estados solo puedan ser 'Disponible' u 'Ocupado') y restricciones UNIQUE (para evitar correos o placas duplicadas)."

3. Inserción de Datos Segura

"En un sistema real, no podemos permitir que las aplicaciones hagan inserciones directas a las tablas. Por eso, desarrollamos Procedimientos Almacenados de inserción para cada tabla. Estos actúan como un filtro de seguridad. Por ejemplo, antes de registrar un nuevo usuario, el procedimiento verifica que el DNI no exista previamente; si existe, el proceso se detiene y devuelve un error amigable gracias al uso de bloques TRY...CATCH, evitando que la base de datos colapse."

4. El Corazón del Sistema: Ingreso Vehicular

"El procedimiento más importante y complejo del sistema es el Registro de Ingreso Vehicular. Aquí aplicamos la lógica de negocio usando Funciones Escalares. Cuando un auto intenta entrar, el sistema hace 5 validaciones: verifica que la placa exista, verifica que el usuario no tenga otro vehículo adentro, y llama a funciones para ver si el usuario tiene multas impagas o está suspendido. Si debe o está castigado, se le niega el ingreso. Si pasa todos estos filtros, busca automáticamente un espacio disponible y genera el Ticket."

5. Automatización y Seguridad con Triggers

"Para quitarle carga de trabajo manual al operador, automatizamos procesos usando Triggers. Primero, el control de espacios: al registrar un ingreso, el espacio cambia automáticamente a 'Ocupado', y al registrar la salida, vuelve a 'Disponible'. Segundo, la calculadora de deuda: al registrar una infracción, un trigger suma automáticamente las deudas del alumno y alerta el total. Y tercero, la auditoría: interceptamos cualquier cambio (INSERT, UPDATE, DELETE) y guardamos el antes y el después exacto en formato XML dentro de la tabla Historial de Auditoría."

6. El Cursor para Penalizaciones

"Finalmente, resolvimos un problema común: ¿Qué pasa con los alumnos que dejan su carro abandonado? Para esto implementamos un Cursor. Este proceso recorre en lote, fila por fila, todos los tickets abiertos. Mediante la función DATEDIFF, calcula las horas de estadía. Si detecta que un vehículo lleva más de 12 horas, le inserta automáticamente una infracción por 'Permanencia Excedida' con una multa de 20 soles."

7. Cierre de la Exposición

"En conclusión, hemos construido un sistema completo y escalable. Usamos Procedimientos y Funciones para aislar y validar la lógica, y usamos Triggers y Cursores para automatizar el mantenimiento del sistema. De esta manera, garantizamos la integridad de los datos en todo momento. Muchas gracias."
